# CLI subcommand verbs

Primary sources only: each command below is copied from that tool's own manual. Hugo is included because `hugo config` prints merged configuration with no `get`, `list`, or `view` child, which the config subcommands of git, gh, npm, pnpm, kubectl, and the AWS CLI do not do.

## Dominant verb for each job

- **Show:** `get` for one key. `list` (mise: `ls`) for many keys. kubectl uses `view`. Hugo uses the bare command `config`.
- **Set:** `set`.
- **Init:** `init` scaffolds a project, module, or working directory. It is not the usual verb for writing one config key. The AWS CLI creates its config file by running `configure` with no further verb. Cargo also has `new`; Hugo content creation is `new`.
- **Schema:** `schema`, and only as `terraform providers schema` among these manuals. kubectl's word for a resource schema is `explain`. mise publishes a JSON schema URL and does not document a `schema` subcommand on the pages cited here.
- **Refresh a cached index:** `update`, on Helm (`helm repo update`). mise's documented refresh of a cached version list is `cache clear`. rustup's command is `update`; its sample log says "syncing channel updates". Terraform's module verb is `get`, with a flag `-update`. Cargo's built-in list has `fetch` and `update`, documented as dependency download and lockfile update, not
  as an index subcommand.
- **Catalogue:** `search`. A list with no query uses `list` / `ls`, `registry`, or `api-resources`.

`show` on these manuals is the active toolchain (`rustup show`) or chart contents (`helm show`), not a config value.

## Wording that fixes the verb, from the same pages

- git-config names the current subcommands `list`, `get`, `set`, `unset`, `rename-section`, `remove-section`, and `edit`. It marks positional `git config <name> <value>`, `--list`, and `--get` as deprecated modes replaced by `set`, `list`, and `get`. The synopsis has no `init`, `schema`, `show`, or `search`. <https://git-scm.com/docs/git-config>
- `gh config get` is "Print the value of a given configuration key". `gh config set` is "Update configuration with a value for the given key". `gh api` "Makes an authenticated HTTP request to the GitHub API and prints the response." <https://cli.github.com/manual/gh_config_get> <https://cli.github.com/manual/gh_config_set> <https://cli.github.com/manual/gh_api>
- Cargo's stable built-in command list does not include `config`. The unstable page says `cargo config` "currently includes the `get` subcommand" and shows `cargo +nightly -Zunstable-options config get build.rustflags`. `cargo update` "will update dependencies in the `Cargo.lock` file". `cargo fetch` is "Fetch dependencies of a package from the network". `$CARGO_HOME/registry/`
  "contains cached downloads of the registry index". `--explain` "Run `rustc --explain CODE`". <https://doc.rust-lang.org/cargo/reference/unstable.html> <https://doc.rust-lang.org/cargo/commands/cargo.html> <https://doc.rust-lang.org/cargo/commands/cargo-update.html>
- npm: "Echo the config value(s)" (`get`), "Sets each of the config keys" (`set`), "Show all the config settings" (`list`). `npm init` with no argument writes a `package.json`. `npm search`: "Search the registry for packages". <https://docs.npmjs.com/cli/v11/commands/npm-config/> <https://docs.npmjs.com/cli/v11/commands/npm-init/> <https://docs.npmjs.com/cli/v11/commands/npm-search/>
- pnpm: `get` "Print the config value"; `set` "Set the config key to the value provided"; `list` "Show all the config settings". `pnpm fetch` "requires `pnpm-lock.yaml` and does not update it". <https://pnpm.io/cli/config> <https://pnpm.io/cli/fetch>
- `kubectl config view`: "Display merged kubeconfig settings". `kubectl explain`: "Format in which to render the schema". `kubectl api-resources`: "Print the supported API resources on the server". <https://kubernetes.io/docs/reference/kubectl/generated/kubectl_config/kubectl_config_view/> <https://kubernetes.io/docs/reference/kubectl/generated/kubectl_explain/>
  <https://kubernetes.io/docs/reference/kubectl/generated/kubectl_api-resources/>
- Docker's subcommand table labels `docker config` "Manage Swarm configs" and `docker search` "Search Docker Hub for images". Client settings are `config.json` plus the `--config` flag ("Location of client config files"). `docker init`: "Creates Docker-related starter files for your project". <https://docs.docker.com/reference/cli/docker/> <https://docs.docker.com/reference/cli/docker/init/>
- `terraform init` "initializes a working directory containing Terraform configuration files". `terraform get` "download and update modules"; `-update` checks already downloaded modules. `terraform providers schema` "print detailed schemas for the providers used in the current configuration". The command overview's list has `show` and `refresh` for state, and no `config`
  subcommand. <https://developer.hashicorp.com/terraform/cli/commands/init> <https://developer.hashicorp.com/terraform/cli/commands/get> <https://developer.hashicorp.com/terraform/cli/commands/providers/schema> <https://developer.hashicorp.com/terraform/cli/commands>
- `helm repo update`: "Update gets the latest information about charts from the respective chart repositories. Information is cached locally, where it is used by commands like 'helm search'." The shared flag `--repository-cache` is "path to the directory containing cached repository indexes". `helm search repo` "looks for matches" in "metadata stored on the system". `helm show
  values` "displays the contents of the values.yaml file". `helm env`: "Env prints out all the environment information in use by Helm." <https://helm.sh/docs/helm/helm_repo_update/> <https://helm.sh/docs/helm/helm_search_repo/> <https://helm.sh/docs/helm/helm_show_values/> <https://helm.sh/docs/helm/helm_env/>
- `aws configure` with no arguments prompts and creates `~/.aws/config` if it does not exist. `get` "Get a configuration value from the config file." `set` "Set a configuration value from the config file." `list` "Lists the profile, access key, secret key, and region". The configure command list has no `schema`, `init`, or `search`.
  <https://docs.aws.amazon.com/cli/latest/reference/configure/index.html> <https://docs.aws.amazon.com/cli/latest/reference/configure/get.html> <https://docs.aws.amazon.com/cli/latest/reference/configure/set.html> <https://docs.aws.amazon.com/cli/latest/reference/configure/list.html>
- rustup examples: `rustup show` "Show which toolchain will be used in the current directory"; `rustup set profile minimal` "Set the default profile"; `rustup override set` sets a directory toolchain. `rustup update` sample output includes "syncing channel updates". `rustup self update` "will not download new toolchains". <https://rust-lang.github.io/rustup/examples.html>
  <https://rust-lang.github.io/rustup/basics.html>
- mise: `settings get` "Show the effective value of a setting". `settings set` "Writes ~/.config/mise/config.toml" (alias `create`). `settings ls` "List configured settings and their sources". `cache clear` example is "Refresh node's version list". `registry` "List registry shorthand names and their backends". `search` "Search for available tools". The configuration page gives
  the schema URL and does not name a subcommand that prints it. <https://mise.jdx.dev/cli/settings/get.html> <https://mise.jdx.dev/cli/settings/set.html> <https://mise.jdx.dev/cli/settings/ls.html> <https://mise.jdx.dev/cli/cache/clear.html> <https://mise.jdx.dev/cli/registry.html> <https://mise.jdx.dev/cli/search.html> <https://mise.jdx.dev/configuration.html>
- `hugo config`: "Display project configuration, both default and custom settings." The command index printed on the Hugo command pages includes `hugo config`, `hugo new`, `hugo mod init`, and `hugo mod get`, and does not include `schema`, `config get`, or `config set`. `hugo mod init`: "Initialize this project as a Hugo Module." `hugo mod get`: "Resolves dependencies in your
  current Hugo project." `hugo new`: "Create new content". <https://gohugo.io/commands/hugo_config/> <https://gohugo.io/commands/hugo_new/> <https://gohugo.io/commands/hugo_mod_init/> <https://gohugo.io/commands/hugo_mod_get/>
